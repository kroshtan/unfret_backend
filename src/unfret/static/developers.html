Ask Unfret before your agent pays

One call per check: does this shop, listing, second-hand ad or tradesperson's site show signs of a scam, dropshipped generic goods, fake reviews or pressure tricks? The answer is an action, allow, warn or block, with the evidence behind it. No account: pay per call over x402, or use a prepaid pass.

Three ways in

The same analysis a shopper gets in the browser extension, for your agent or your code.

  • MCP server

    For Claude, Cursor and any MCP client. The agent pays each check from its own Solana wallet, within spending caps you set.

  • HTTP with x402

    Call /v1/check, answer its 402 with a payment in USDC or wSOL, and call again. Unfret pays the network fee.

  • Prepaid pass

    No wallet: buy checks by card, iDEAL | Wero or crypto, and send the pass as a bearer token, like an API key.

Two tiers, priced per check

In US dollars: USDC pays them exactly, wSOL at the live SOL/USD price. A page Unfret can't read costs nothing, and paying twice for the same request is impossible.

The MCP server

unfret-mcp (on PyPI, and in the MCP registry as net.unfret/mcp) gives an agent three tools: check_store, explain_flag and get_pricing. It pays each check from the agent's own Solana wallet in USDC, or wSOL when that's what the wallet holds, and refuses to spend beyond its caps. It needs uv.

{"mcpServers": {"unfret": {
  "command": "uvx", "args": ["unfret-mcp"],
  "env": {"UNFRET_MCP_KEYPAIR": "~/.config/solana/agent.json"}}}}

Give the agent a wallet of its own holding only what it may spend, never your main wallet.

UNFRET_MCP_KEYPAIRThe agent's Solana keypair file

HTTP with x402

  1. Ask. POST {{base_url}}/v1/check with {"url", "tier", "policy"}, and page_content (the page's HTML) for marketplaces such as Amazon that refuse server-side visits.
  2. Pay. The answer is 402 with a PAYMENT-REQUIRED header listing what it accepts: USDC and wSOL on {{network_name}}, scheme exact. Unfret is the fee payer, so you pay only the price.
  3. Ask again with the payment in PAYMENT-SIGNATURE. The same signature always gets the same answer and is never charged twice.

Every error is JSON with detail and error_code, and says whether you were charged. The full rules, errors and response fields are in llms.txt and the x402 discovery document.

A prepaid pass as an API key

No wallet needed: buy checks by card or iDEAL | Wero (or with crypto), and use the Unfret pass you get as a bearer token. One analysis is one check; My checks shows what's left.

curl {{base_url}}/v1/analyze \
  -H "Authorization: Bearer $UNFRET_PASS" \
  -H "Content-Type: application/json" \
  -d '{"url": "https://shop.example/p/42"}'

The answer is the shopper's verdict (a band, a headline, reasons and what looks good) with the score behind it. /v1/analyze/stream sends progress as server-sent events.

Machine-readable

  • llms.txt: the service described for language models
  • /.well-known/x402: tiers, prices, assets and policies
  • openapi.json and the API reference
  • accuracy.json: how often each verdict is right, from the accuracy page
  • Source code, MIT licensed, including the trained scorers and the MCP server
