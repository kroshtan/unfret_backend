For developers and shopping agents

Ask Unfret before your agent pays

One call per check: does this product on a marketplace or web shop, second-hand ad, or tradesperson's or local service's website show signs of a scam, dropshipped generic goods, fake reviews or pressure tricks? The answer is an action, allow, warn or block, with the same risk level (0 to 4) a shopper sees and the evidence behind it. Use it from an MCP client, from the API with an Unfret pass, or pay per call over x402 with no account.

  • Developer pass: {{developer_checks}} free deep checks, then packs of checks. Quick checks are free.
  • x402: {{quick_price}} quick, {{deep_price}} deep, paid per call in {{payment_options}}.
  • Shoppers check for free in the extension, the app and on this site; this page is for code.

Three ways to integrate

All three run the same check shoppers get for free in the browser extension. The examples check the test shop, a made-up store with every trick Unfret catches.

  1. 1. MCP server

    For Claude, Cursor and any MCP client. Remote at {{base_url}}/mcp with an Unfret pass, or without a header: the client asks you to sign in. Or local with uvx unfret-mcp, paying from a pass or the agent's own wallet. Tools: a free quick check, a deep check, checks left and prices.

    claude mcp add --transport http unfret {{base_url}}/mcp \
  --header "Authorization: Bearer $UNFRET_PASS"

  2. 2. API with a pass

    POST /v1/check with Authorization: Bearer ufk_…. A deep check uses one of the pass's checks, a quick check is free. Make a developer pass (free checks, no account) or buy checks.

    curl {{base_url}}/v1/check -H "Authorization: Bearer $UNFRET_PASS" \
  -H "Content-Type: application/json" \
  -d '{"url": "{{base_url}}/test-shop", "tier": "deep"}'

  3. 3. x402 pay-per-call

    No pass, no account: the agent pays each call from its own wallet, {{quick_price}} for quick and {{deep_price}} for deep, in {{payment_options}}. Unfret answers 402 with the price; the agent pays and sends the same request again.

    # 1. ask: 402, with the options in PAYMENT-REQUIRED
curl -i {{base_url}}/v1/check -H "Content-Type: application/json" \
  -d '{"url": "{{base_url}}/test-shop", "tier": "deep"}'
# 2. pay one of its accepts[] with an x402 client
# 3. ask again with the payment: 200 + PAYMENT-RESPONSE
curl {{base_url}}/v1/check -H "PAYMENT-SIGNATURE: $PAYMENT" \
  -H "Content-Type: application/json" \
  -d '{"url": "{{base_url}}/test-shop", "tier": "deep"}'

Get a developer pass

{{developer_checks}} free deep checks, for trying Unfret out as you build and test your agent: a few seconds of work in this browser, no account. One per browser, and one a day per network. Quick checks are always free.

The free checks are for the API and the MCP server (POST /v1/check). After them, buy a pack of checks for the pass: {{packs_line}}. No subscription, and checks don't expire.

Or in code: Unfret().new_developer_pass() (Python), or GET /v1/keys/challenge?developer=true, then POST /v1/keys with the solved challenge and "developer": true (the proof of work, step by step). Buy checks for any pass.

A full response

Unfret's answer for the test shop: a deep check with a pass, recorded on {{sample_server}} on {{measured_on}}. With x402 the body is the same without the pass's four fields (charged, free_check, free_checks_left, balance_usd_micros), and comes with a PAYMENT-RESPONSE header. The MCP tools return the same verdict.

{{sample_json}}

action follows the request's policy (strict, balanced or lenient); band is what a shopper would see: reliable "Looks fine", concerns "Worth a look", careful "Think twice", junk_or_scam "Serious concerns". risk is the overall risk level, higher is worse (0 none, 1 pressure and tricks, 2 may cost more than it's worth, 3 may not work as described, 4 may not arrive or may not be safe), with because, the findings behind it, worst first. Flags are evidence, never a verdict that a shop is a scam.

1. The MCP server

For Claude, Cursor and any MCP client. Every tool has a title and explicit hints: the free check is read-only, the deep one uses one of the pass's checks, and both read a third-party page.

Remote, at {{base_url}}/mcp

Streamable HTTP, authenticated with an Unfret pass or by signing in. It never pays from a wallet. Tools: check_store_quick (free), check_store_deep (one of the pass's checks), get_checks_left and get_pricing. In Claude Code:

claude mcp add --transport http unfret {{base_url}}/mcp \
  --header "Authorization: Bearer $UNFRET_PASS"

Or in a client's JSON settings:

{"mcpServers": {"unfret": {
  "type": "http", "url": "{{base_url}}/mcp",
  "headers": {"Authorization": "Bearer ufk_…"}}}}

Or sign in, without a header. Claude's connectors (claude.ai, Claude Desktop and mobile), Claude Code and other clients that speak MCP's OAuth just add {{base_url}}/mcp. Before you sign in, the client can already connect, list the tools and call get_pricing; a check is what asks you to sign in. Unfret's sign-in page makes a pass for you (or takes one you have), and the client gets a token for it. The token works at /mcp only, lasts an hour and is renewed by the client; disconnect in the client, or replace the pass with its backup code, to end it. No payment is part of signing in. For client developers: discovery at /.well-known/oauth-protected-resource/mcp, public clients only (PKCE S256), with a Client ID Metadata Document or dynamic registration; codes go only to Claude's callback and loopback addresses.

Step by step for Claude, with example prompts and troubleshooting: Unfret in Claude.

Local, with a pass or a wallet

unfret-mcp (on PyPI, and in the MCP registry as net.unfret/mcp) runs next to your agent with uv. Tools: check_store (with a tier), explain_flag and get_pricing. With a pass:

{"mcpServers": {"unfret": {
  "command": "uvx", "args": ["unfret-mcp"],
  "env": {"UNFRET_PASS": "ufk_…"}}}}

Or paying each check over x402 from the agent's own wallet, refusing to spend beyond its caps: on Solana in USDC, or wSOL when that's what the wallet holds, or in USDC on Base with an EVM key (UNFRET_MCP_BASE_KEY, version 0.3.0 or newer):

{"mcpServers": {"unfret": {
  "command": "uvx", "args": ["unfret-mcp"],
  "env": {"UNFRET_MCP_KEYPAIR": "~/.config/solana/agent.json"}}}}

Give the agent a wallet of its own holding only what it may spend, never your main wallet. Paying from a pass (UNFRET_PASS) needs version 0.2.0 or newer.

2. The API with an Unfret pass

A pass is an API key: send it as Authorization: Bearer ufk_… to POST /v1/check (above). No wallet needed: make a developer pass, or buy checks by card or iDEAL | Wero (or with crypto) for any pass. GET /v1/credits with the pass says what's left, and every answer carries free_checks_left and balance_usd_micros; GET /v1/pricing has the prices. The HTTP guide has the request, the response, the errors and examples in curl, JavaScript, Go and PHP.

For the card a shopper sees (a band, a headline, reasons and what looks good), POST /v1/analyze takes the same pass and streams progress at /v1/analyze/stream; a developer pass's free checks don't count there, only bought ones. Your developer pass shows what's left.

Passes don't expire. Neither do the checks on them, and Unfret doesn't delete a pass for not being used. A pass stops working when it is replaced with its backup code or deleted on request. Unfret can also retire old passes in a one-off clean-up, as at the fresh start when free checks began; by default such a clean-up refuses to touch passes that bought checks. A retired or replaced pass answers 401 INVALID_API_KEY.

3. x402 pay-per-call, step by step

  1. Ask. POST {{base_url}}/v1/check with {"url", "tier", "policy"}, and page_content (the page's HTML) for marketplaces such as Amazon that refuse server-side visits.
  2. Pay. The answer is 402 with a PAYMENT-REQUIRED header (base64 JSON, also the body) whose accepts lists what Unfret takes: {{payment_options}}, scheme exact. Pay one with an x402 client library (the x402 project has them for TypeScript, Python and Go) or unfret-mcp. On Solana you sign a token transfer and Unfret pays the network fee, so you pay only the price. On Base you sign a USDC transferWithAuthorization (EIP-3009); the facilitator pays the gas, and it is settled only once the answer is ready, so a failed check costs nothing.
  3. Ask again with the payment in PAYMENT-SIGNATURE. The answer carries a PAYMENT-RESPONSE header. The same payment always gets the same answer and is never charged twice.

Copy-paste examples with the official x402 SDKs, one file each, for Solana (USDC or wSOL) and Base (USDC), plus the call with a pass: Python and TypeScript (GitHub mirror). They run against dev (Solana devnet, Base Sepolia) by default; UNFRET_ENV=production switches to unfret.net.

Every error is JSON with detail and error_code, and says whether you were charged. The full rules, errors and response fields are in llms.txt and the x402 discovery document.

A Python client, and any other language

Python: unfret-client, MIT licensed, with a pass: check(url) answers allow, warn or block from the verdict a shopper would see ("Looks fine" → allow, "Worth a look" → warn, "Think twice" and "Serious concerns" → block; change it with policy).

{{python_install}} 
from unfret_client import Unfret

decision = Unfret(pass_="ufk_…").check("https://shop.example/p/42")
if decision.action == "block": ...

Any other language: it's one HTTPS call. Use Unfret from any language has the request, the response, the errors and the developer pass's proof of work, with examples in curl, JavaScript, Go and PHP.

JavaScript and TypeScript: there's no package on npm. The TypeScript reference client is one file without dependencies, MIT licensed, to copy from the repository into your project (GitHub mirror).

The source: Python client, TypeScript reference client, copy-paste examples (a pass, and x402 on Solana and on Base, in Python and TypeScript) and an example agent that checks the shop before checkout.
