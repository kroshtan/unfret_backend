Ask Unfret before your agent pays

One call per check: does this product on a marketplace or web shop, second-hand ad, or tradesperson's or local service's website show signs of a scam, dropshipped generic goods, fake reviews or pressure tricks? The answer is an action, allow, warn or block, with the evidence behind it. No account: pay per call over x402, or use an Unfret pass. A developer pass comes with {{developer_checks}} free deep checks, for the API and the MCP server.

Get a developer pass

{{developer_checks}} free deep checks, for trying Unfret out as you build and test your agent: a few seconds of work in this browser, no account. One per browser, and one a day per network. Quick checks are always free.

The free checks are for the API and the MCP server (POST /v1/check): they don't count in the Unfret extension, the phone app or the link checker on this site. Checks you buy for the pass work everywhere.

Or in code: Unfret().new_developer_pass() (Python), or GET /v1/keys/challenge?developer=true, then POST /v1/keys with the solved challenge and "developer": true (the proof of work, step by step). Buy checks for any pass.

The MCP server

For Claude, Cursor and any MCP client. Every tool has a title, a one-sentence description and explicit hints: the free check is read-only, the deep one uses one of the pass's checks, and both read a third-party page.

Remote, with a pass

Streamable HTTP at {{base_url}}/mcp, authenticated with an Unfret pass or by signing in. It never pays from a wallet. Tools: check_store_quick (free), check_store_deep (one of the pass's checks), get_checks_left and get_pricing. In Claude Code:

claude mcp add --transport http unfret {{base_url}}/mcp \
  --header "Authorization: Bearer $UNFRET_PASS"

Or in a client's JSON settings:

{"mcpServers": {"unfret": {
  "type": "http", "url": "{{base_url}}/mcp",
  "headers": {"Authorization": "Bearer ufk_…"}}}}

Or sign in, without a header. Claude's connectors (claude.ai, Claude Desktop and mobile), Claude Code and other clients that speak MCP's OAuth just add {{base_url}}/mcp. Listing the tools and the prices needs no sign-in; the first check asks for it. Unfret's sign-in page makes a pass for you (or takes one you have), and the client gets a token for it. It works at /mcp only, lasts an hour and is renewed by the client; disconnect in the client, or replace the pass with its backup code, to end it. No payment is part of signing in. For client developers: discovery at /.well-known/oauth-protected-resource/mcp, public clients only (PKCE S256), with a Client ID Metadata Document or dynamic registration; codes go only to Claude's callback and loopback addresses.

Local, with a pass or a wallet

unfret-mcp (on PyPI, and in the MCP registry as net.unfret/mcp) runs next to your agent with uv. Tools: check_store (with a tier), explain_flag and get_pricing. With a pass:

{"mcpServers": {"unfret": {
  "command": "uvx", "args": ["unfret-mcp"],
  "env": {"UNFRET_PASS": "ufk_…"}}}}

Or paying each check from the agent's own Solana wallet, in USDC, or wSOL when that's what the wallet holds, refusing to spend beyond its caps:

{"mcpServers": {"unfret": {
  "command": "uvx", "args": ["unfret-mcp"],
  "env": {"UNFRET_MCP_KEYPAIR": "~/.config/solana/agent.json"}}}}

Give the agent a wallet of its own holding only what it may spend, never your main wallet. Paying from a pass (UNFRET_PASS) needs version 0.2.0 or newer.

A Python client, and any other language

Python: unfret-client, MIT licensed, with a pass: check(url) answers allow, warn or block from the verdict a shopper would see ("Looks fine" → allow, "Worth a look" → warn, "Think twice" and "Serious concerns" → block; change it with policy).

{{python_install}} 
from unfret_client import Unfret

decision = Unfret(pass_="ufk_…").check("https://shop.example/p/42")
if decision.action == "block": ...

Any other language: it's one HTTPS call. Use Unfret from any language has the request, the response, the errors and the developer pass's proof of work, with examples in curl, JavaScript, Go and PHP.

JavaScript and TypeScript: there's no package on npm. The TypeScript reference client is one file without dependencies, MIT licensed, to copy from the repository into your project (GitHub mirror).

The source: Python client, TypeScript reference client, and an example agent that checks the shop before checkout.

HTTP with x402, step by step

  1. Ask. POST {{base_url}}/v1/check with {"url", "tier", "policy"}, and page_content (the page's HTML) for marketplaces such as Amazon that refuse server-side visits.
  2. Pay. The answer is 402 with a PAYMENT-REQUIRED header listing what it accepts: {{payment_options}}, scheme exact. Today x402 here is Solana only; USDC on Base is coming next. Unfret (or, on Base, the facilitator) pays the network fee, so you pay only the price. On Base you sign a USDC transferWithAuthorization, and it is settled only once the answer is ready.
  3. Ask again with the payment in PAYMENT-SIGNATURE. The same payment always gets the same answer and is never charged twice.

Every error is JSON with detail and error_code, and says whether you were charged. The full rules, errors and response fields are in llms.txt and the x402 discovery document.

An Unfret pass as an API key

No wallet needed: buy checks by card or iDEAL | Wero (or with crypto), and send the pass as a bearer token to /v1/check (above) or to /v1/analyze, which answers with the shopper's verdict (a band, a headline, reasons and what looks good) and streams progress at /v1/analyze/stream. My checks shows what's left.

Passes don't expire. Neither do the checks on them, and Unfret doesn't delete a pass for not being used. A pass stops working when it is replaced with its backup code or deleted on request. Unfret can also retire old passes in a one-off clean-up, as at the fresh start when free checks began; by default such a clean-up refuses to touch passes that bought checks. A retired or replaced pass answers 401 INVALID_API_KEY.
